# 重庆轨道到站 · Scripting

将 [`MetroMinutes`](./MetroMinutes) 导入 iPhone 的 Scripting App。原生 Swift 项目仍保留在仓库中，本页说明脚本版。

## 1.4.0 · 默认候车倒计时

- 桌面默认显示到站倒计时。参数留空、`scene:work` / `scene:home`、旧格式参数或普通分享码都使用候车布局；保存通勤场景不再自动把组件切成出门建议。
- 自动切班、已确认停靠且有有效发车时间时的停站倒计时、近三班缓存推算继续保留。沿用原来的兼容 / 自动选择，不重置已保存的站点、场景或缓存。
- **添加桌面组件 → 组件内容** 可选择“候车倒计时（默认）”或“通勤建议”，预览、尺寸说明和复制参数同步切换。通勤建议使用 `commute:work` / `commute:home`，可与候车组件同时添加；尚未保存通勤场景也能直接预览、复制候车参数。
- App 内保留上班 / 回家、出门建议、目的站可达判断、分享导入和锁屏计时。点击场景绑定的候车组件进入 App 时，仍保留完整场景。
- 下车站改成点击后进入带搜索框的选择列表；边搜索边点选，选中后直接返回。取消不改选择，重新打开清空搜索，不再要求在外面输入后再打开下拉选择。

**升级提示：** 之前用 `scene:work` / `scene:home` 的组件会在重新加载后恢复候车倒计时。希望保留出门建议时，在 App 中选择“通勤建议”并重新复制参数即可；大号候车组件显示同站双向，大号通勤建议组件仍可显示上班和回家。

## 1.3.0 · 通勤场景

六项产品功能已接入同一条使用流程，不依赖 Scripting Pro：

1. **赶车建议**：预计发车时间减去步行、进站和缓冲时间，推荐近三班中仍来得及且已确认可直达的班次；显示出门倒计时和绝对截止时间。
2. **上班 / 回家**：分别保存上下车站、方向、耗时和主题，一键切换；按上海时间推荐场景，但不自动改动用户选择。
3. **目的站判断**：区分“普通车可乘”“直快/快速可乘”“本班不直达”“停靠待确认”；待确认、缺失发车时间和失败/过旧的数据不进入赶车推荐。
4. **首次引导**：四步完成上车站、方向与下车站、到站耗时、确认保存，随后预览和引导添加桌面组件。保存前可取消；下车站支持关键字筛选。
5. **分尺寸布局**：小号突出出门建议；中号增加查询时近三班；大号上下展示上班和回家，每个场景独立刷新。通勤组件隐藏版本等调试信息，在设置内查看。
6. **配置分享**：复制场景配置码，接收者粘贴后先校验、预览，再选择保存或覆盖哪个场景。只导出配置，不包含班次缓存。

详见 [通勤使用说明与判断边界](./COMMUTE.md)。当前 1.4.0 默认候车倒计时，通勤建议改用 `commute:work` / `commute:home` 显式选择。两类组件可同时使用。

新通勤自动模式每个场景最多 4 张建议卡、3 个遮罩，不增加到每秒更新一层；沿用 1.2.2 的置顶按钮和点击边界。推荐在查询满 5 分钟时停止；兼容模式保持查询时画面，需在出门截止或有效期后刷新。

## 1.2.1 的兼容模式与精简布局

- 针对用户在 iOS 18 / iOS 26 上反馈的桌面白屏，增加默认的 **兼容模式**：每个方向仅展示当前班次，不构建遮罩、滤镜和未来画面。原生倒计时仍会走，到零后请刷新；状态和选班在系统或手动重新加载组件时更新。
- 保留可选 **自动切班（精简版）**。沿用用户已验证的 Demo 遮罩写法，每方向从最多 15 张完整状态画面缩减为 **最多三张班次卡 + 一张结束提示**。到站只切换小块倒计时/状态区域；不再为“即将到达”“即将发车”复制整张卡片。这两类提示继续在 App 页面中显示。
- 自动模式最多预建 6 个倒计时、7 个遮罩/方向，其中完整卡片遮罩最多 3 个。停靠待确认或缺失发车时间的班次不生成发车倒计时。小号仅展示所选方向，中号/大号展示双向。
- 自动模式用单独一行切换 5 分钟旧数据提示；三班用完或数据满 30 分钟时覆盖计时区域并提示刷新，以先到者为准。结束提示持续保留，不循环、不外推第四班。
- App 的“桌面显示模式”可恢复已经白屏的组件，设置应用于本机所有 MetroMinutes 组件，不改动站点参数。底部显示版本号及 **兼容 / 自动**，便于核对更新是否生效。
- 刷新按钮仍在遮罩层外。手动刷新重新查询，切换显示模式只保存设置并申请重新加载，不额外请求接口。

已有功能继续保留：

- 保留接口的停站标记，结合用户提供的四张时刻表、方向及停靠站，显示 **快速 / 直快 / 疑似快速 / 疑似直快**。没有充分证据时显示 **停靠待确认**，不因 `skip_stop_flag=2` 删除记录。
- 时刻匹配允许 **前后 10 分钟**。宽范围匹配必须同时有标记 `2`、正确的本站/线路/方向/终点信息，且只有一个候选；不会把窗口内普通班次全部改成快车。规则与来源见 [TIMETABLES.md](./TIMETABLES.md)。
- 页面无需再次联网，即可根据上次响应推算到达、停站、发车和下一班。每秒更新本地时间，不每秒请求接口。
- 有可靠的停靠判断和有效预计发出时间时，停站阶段显示 **距预计发车** 倒计时；没有发出时间就不显示发车倒计时。停靠未知的记录也不显示“停站中”。
- 桌面展示相同状态、快车标记、到发时间和数据来源；锁屏为选定单班展示预计到达，以及有条件显示的预计发车倒计时。
- 复制小组件参数功能保留。

**验证范围：** 69 项 Node 自动测试、TS/TSX 语法、纯数据模块严格类型及入口依赖检查通过。覆盖协议、停靠判断、三班推算、到站及停站计时、刷新、通勤建议、分享校验与场景隔离；真实页面处理函数覆盖引导、搜索选择、保存、两种组件内容的预览/复制、分享和导入。新增验证保存场景后的默认候车布局、三种尺寸/两种渲染方式、显式通勤参数、独立配置及进入 App 时的场景保留。**本地测试不模拟 iOS 原生命中测试、遮罩渲染、像素排版、键盘或内存占用，也不等同于 Scripting 原生 API 完整类型检查；仍需 iOS 18/26 实机验证。**

## 使用

1. 运行 **MetroMinutes**，按四步引导保存场景，或“稍后设置”继续查看旧站点的到站数据。
2. 在看板切换 **上班 / 回家**；未配置的场景会进入引导。编辑其中一个不会覆盖另一个。
3. 点 **添加桌面组件**，默认选择候车倒计时，预览尺寸后复制参数。参数留空跟随当前站点或场景；`scene:work` / `scene:home` 绑定场景并显示候车倒计时。无需配置通勤场景也能添加。
4. 需要出门建议时，将 **组件内容** 改为 **通勤建议**，复制 `commute:work` / `commute:home` 参数到对应组件。此选择只决定复制、预览的内容，不改变其他桌面组件。
5. 分享使用 **分享 / 导入通勤配置**。锁屏使用 **显示设置与锁屏计时 → 跟踪当前班次（锁屏）**，仍只跟踪单班。

手动参数示例（也可使用完整配置 JSON）：

```text
头塘|4号线|up|timer|dark
兰花路|10号线|down|timer|light
```

格式：`站名或站号|线路名或线路号|up或down|timer|dark或light`。换乘站必须指定线路。环线的 up/down 保持接口方向，不凭名称猜测内外环。

## 状态和缓存推算

下表描述 App 内的动态状态。自动切班模式保留选班和到站/停站切换，但省去 30 秒“即将到达”、15 秒“即将发车”两个视觉阶段；兼容模式只在重新加载时选择状态，计时归零不会主动切换文字或下一班。

| 时刻 / 数据情况 | 显示 |
| --- | --- |
| 尚未到预计到达时间 | 预计到达 + 到达倒计时 |
| 距预计到达不超过 30 秒 | 预计即将到达 |
| 到达后、发出前，停靠已确认 | 预计停站中 + 发车倒计时 |
| 距预计发出不超过 15 秒 | 预计即将发车 |
| 缺少或无效的预计发出时间 | 预计已到站 · 发车时间未知，不显示发车倒计时 |
| 停靠尚未确认且到达时间已过 | 已到预计时刻 · 停靠待确认，不声称正在停站 |
| 超过有效预计发出时间 | 切换下一条已知班次；页面注明上一班预计已驶离 |
| 本批班次全部用完 | 自动模式显示班次数据已用完 · 请刷新，不外推第四班 |
| 查询已过 5 分钟 | 明确标记旧数据推算 |
| 查询已满 30 分钟 / 时间异常 | 停止推算；自动模式若仍有未结束卡片，显示失效提示；已结束的刷新提示不再增加画面 |

所有状态都是预测，不是车辆位置或开关门实况。原始查询时间不会因推算或请求失败而改写。无发出时间的班次，在到达后最多保留 60 秒的“发车时间未知”提示（或下一班到达即切换）；该窗口不代表实际停站 60 秒，不据此声称已驶离。

普通加载在 5 分钟内复用成功缓存，状态变化不需要 HTTP 请求。手动刷新始终绕过缓存。网络失败保留原始响应及查询时间，显示失败提示；失败后 20 秒内避免重复请求。30 分钟是本脚本选择的推算上限，不是接口保证。

### 桌面与锁屏边界

兼容模式只在系统重新运行组件时选择下一班，原生倒计时归零不会触发选班。选择此模式意味着优先使用简单视图恢复显示；查询时间和状态文字在下一次加载前保持不变，需按底部提示刷新。

自动模式通过 `ProgressView(timerFrom/timerTo)`、缩放、亮度转透明度与 `mask` 控制显隐。1.2.0 的每方向最多 15 张完整状态画面，已在 1.2.1 中合并为最多 4 张卡片，到站时仅覆盖小块计时区域。完整卡片与区域覆盖层均有不透明背景，刷新按钮在层外。各方向独立切换，更新时从当前时间继续，不重播过期班次。

遮罩在边界附近的约 2 秒区间内变化，实际切换粒度由系统原生渲染决定，不是精确回调。自动模式仍需要实机验证；Demo 的成功不等于正式组件所有布局都已验证。两种模式没有按 iOS 版本强制分流，可以在同一手机上对照。

系统重新加载申请按查询的新鲜度安排（正常以 5 分钟为目标，失败或已过期后约 1 分钟申请重试），仍可能延迟。自动模式中已有三班之间的视觉切换无需再次联网或重跑脚本；兼容模式则依赖重新加载来更新选班。手动刷新始终可以校准数据，查询时间只在获得新响应时改变。

锁屏 / 灵动岛的视图是系统快照，JavaScript 不会在关闭页面后持续更新。锁屏同时展示单班到达计时和（已确认停靠且有发出时间时）发车计时；灵动岛紧凑视图标明“发车 / 到达 / 待确认”。锁屏不会自动切下一班，到零后请更新。实时活动过期时间取该班发出时间（缺失时取到达时间）与查询后 30 分钟的较早者，过期不保证系统立即移除画面。

## 停站字段核查与历史修正

官方旧页面 `metroTrends` 将 `skip_stop_flag=2` 显示为“本站不停靠”，而 `metroTrendsV2` 没有读取该字段。两者使用同一查询接口，不能把旧页面文案、V2 的无差别展示，或标记 `2` 单独当成重庆所有交路的可靠结论。

1.0.2 曾恢复这些记录但没有保留停站标记用于展示；1.1.0 修正这一点，显式保留字段并显示证据和不确定性。头塘 `2026-11-09 09:51:08` 的真实响应在 `tests/fixtures/toutang-20261109.json`。其中往民安大道的 `10:00:25` 班次不会被删除，但没有头塘本站时刻表或明确跨线终点时仍为“疑似直快 · 停靠待确认”。
