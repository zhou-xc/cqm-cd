# 候车与通勤场景 · 1.4.0

桌面默认显示候车倒计时，通勤建议为可选内容；App 内保留全部通勤功能，两类组件都无需 Scripting Pro。

## 第一次使用

打开 MetroMinutes，选择上车线路/站点、乘车方向、下车站，再填写步行到站口、进站安检到站台、额外预留的分钟数。缓冲至少 1 分钟；步行支持 0–60 分钟，进站 0–30 分钟，缓冲 1–15 分钟。

确认后保存为“上班”，按页面说明预览、添加桌面组件。返回看板，切换“回家”即可配置第二个场景。取消引导不会保存半成品。版本、显示模式及候车/锁屏入口在“显示设置与锁屏计时”中。

选择下车站时，点击“下车站”进入选择列表，在列表顶部直接搜索，点中结果即返回。取消不改原选择，重新打开恢复完整列表；上车站不会出现在下车候选中。

“添加桌面组件”默认选择候车倒计时；需要出门建议时，主动切换“组件内容”为通勤建议，再预览、复制参数。暂未保存通勤场景时也能添加候车组件；通勤建议需先保存完整场景。

04:00–13:59 推荐查看上班，14:00–次日03:59 推荐查看回家，按上海时区计算。推荐只提供切换按钮，用户仍控制当前场景，不依赖后台定时唤醒。

## 如何给出建议

出门截止 = 本站预计发车时间 − 步行耗时 − 进站耗时 − 额外预留。

例如班次预计 9 分钟后发车，步行 5 分钟、进站 2 分钟、预留 1 分钟，当前建议在约 1 分钟内出门。选择近三条已知班次中仍满足截止时间的第一条，不预测第四班。

以下条件需同时成立：

- 已配置上下车站和到站耗时。
- 本站停靠可确认，所选下车站在已核实的前方直达区段内。
- 预计发车时间有效且已知。
- 查询匹配本站/线路，未满 5 分钟，最近请求没有失败，时间无异常。

不满足的班次仍展示，不会因为标记 2 被删除。待确认班次不推荐；如果只有不直达或来不及的班次，提示查询后续班次。该建议基于预计时间，不代表列车位置、车门状态或保证能赶上。

## 目的站判断范围

- 普通车：4号线、10号线的同线前方区段按仓库所含官方站点目录顺序核对，同时检查所选方向和本班实际终点，避免越过短线终点。4号线西延站点不按 stationID 数值排序。
- 其他普通车：当前只确认接口明确终点与所选下车站一致的情况；中途经过顺序尚未核实则标注待确认。环线不由 up/down 猜测内外环。
- 直快：仅当现有规则已识别交路，按用户图片中的唐家沱—跳磴停靠顺序判断下车站是否在前方，不把反向或已过站算作可达。
- 10号线快速：当前停靠表仅支持已识别的往王家庄方向。反向不套用该表。后堡等不在表中的下车站不会推荐快速车。
- 未做换乘规划；“不直达”不表示整个线网无法到达。

数据来源是仓库 `Resources/stations.json`（官方站点接口采集，见 `tools/prepare-data.cjs`）及 [TIMETABLES.md](./TIMETABLES.md) 所列用户图片。图片的 ±10 分钟匹配、冲突和待确认规则保持原样。目录不是运行保证，临时调图及未核实交路不补造停靠信息。

## 组件尺寸与刷新

| 类型 | 展示 |
| --- | --- |
| 默认小号候车组件 | 所选站点、方向、到站倒计时和有依据的停站发车倒计时 |
| 默认中号 / 大号候车组件 | 同站双向倒计时；大号增加后续班次 |
| 小号通勤组件 | 当前场景、上下车站、建议班次、出门倒计时、耗时及数据有效时间 |
| 中号通勤组件 | 左侧建议，右侧查询时的近三班到发时间和可乘判断 |
| 大号通勤组件 | 上班与回家各一块，每块有独立刷新按钮；未配置另一场景时提示配置 |

候车组件保留自动切班：按一次查询得到的近三班推算到站、停站与下一班。只有停靠确认且发车时间有效时才显示发车倒计时；五分钟后标旧数据，三班用完或满三十分钟时停止推算并提示刷新。兼容模式倒计时会继续走，状态及下一班需系统或手动重载后更新。已有兼容 / 自动选择不因升级改变。

自动模式为每个通勤场景最多预建 3 张推荐卡和 1 张结束提示。过了出门截止后切到下一条有依据的建议；数据满 5 分钟时停止推荐，不延长原始查询时间。后续卡片没有隐藏按钮，刷新独立置顶并限定点击区域。

兼容模式只生成当前建议。原生倒计时继续走，但文字和推荐班次不会在后台重算；到零或超过底部标明的有效期，请刷新。右侧“查询时的近三班”是该次查询的列表，不冒充实时更新。

大号的两场景可属于不同站点/线路，分别使用自己的响应与查询时间；同站同线复用一次请求。点击某场景的刷新按钮只强制查询该站，其他站正常复用缓存。两块使用当前场景主题以保持统一背景。

## 配置、分享和升级

- 参数 `scene:work` 或 `scene:home` 绑定本机已保存场景并显示**候车倒计时**；以后修改场景不必重新复制参数。从 1.3.x 升级后，这两种参数会恢复候车布局。
- 参数 `commute:work` 或 `commute:home` 显式选择**通勤建议**；在 App 的“添加桌面组件”中切换内容即可复制。两种内容可以同时放在桌面，互不改变对方的配置。
- 留空跟随 App 当前站点或场景并显示候车倒计时；原 `站点|线路|方向|timer|主题` 和旧偏好 JSON 参数保持候车模式。
- “复制分享码”导出 `CQMETRO1:` 开头的完整配置。接收方粘贴后校验、预览，选择存为上班或回家，再明确保存。已有同名场景时按钮显示“覆盖保存为…”。
- 分享码只包含配置白名单字段，不包含缓存、请求结果或账号信息。格式、版本、站点、方向、同站上下车、耗时范围均校验；校验失败不写存储。
- 直接将 `CQMETRO1:` 分享码用作组件参数时，默认显示该配置的候车倒计时；加 `commute:` 前缀可显式查看该配置的通勤建议。此类完整配置不跟随本机场景更新，大号也只展示该配置。
- 场景、旧站点偏好、缓存及显示模式使用独立存储。升级不重置兼容/自动选择，也不把旧候车参数自动改成通勤参数。

## 验证范围

Node 测试覆盖计算与交路边界、三班上限、过期和失败、导入校验、场景隔离、页面真实事件处理流程，以及三种尺寸/两种模式的组件树和刷新动作。没有 iOS 原生渲染器；iOS 18 / 26 上的字号、裁切、动态遮罩、系统重载与点击命中仍需实机验证。
